# 播放队列的所有权归 Media3 播放器，不维护平行状态机

最初实现了一个纯 Kotlin 的 `PlayQueue`（含 15 条单元测试）来管顺序/循环/随机。接入服务前判定它必须删掉：Media3 的 `Player` 本身就持有 timeline，并且通知栏、锁屏、蓝牙线控与流体云上的"上一曲/下一曲"全部以它为准；再养一份平行队列，两边对"下一首是谁"的理解必然漂移。

替代方案是把模式映射到播放器的原生设置（`PlayModeMapping`：`REPEAT_MODE_OFF/ALL/ONE` + `shuffleModeEnabled`），队列内容则通过 `MediaItem` 列表下发，每首歌的可解码信息用 `SongCodec` 编码进 mediaId 一起传下去，由服务侧惰性解析真实播放地址。

## 后果

- 播放模式不再由应用层计算，UI 读 `player.repeatMode/shuffleModeEnabled` 反解即可，不会出现"界面显示随机、实际顺序播"。
- `PlayQueue` 那 15 条测试随之删除；被保留下来的是真正需要应用层负责的部分：`SongCodec` 与 `PlayModeMapping`，各有 JVM 测试。
