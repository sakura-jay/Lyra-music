# 共享元素转场：保留路由转场，把封面交给覆盖层形变

> 本 ADR 是给 `v0.9.3`（M10）预先写下的决策。**方案 A 已经落地**（工单 010 迷你条 ↔ 播放页、
> 工单 011 卡片 ↔ 详情页头），方案 B 没有启用过——两套位移没有打架。写在这里而不是等开工时再补，
> 是因为它约束的是 `v0.9.2` 已经定下的两件事：路由转场的数值不动、封面这类"跨页面的连续性"
> 归 large 档（350/450）。下面"方案 A"一节里的**具体约束**有一条已被实测推翻，见文末的落地修正。

M10 要做两处连续性：**迷你播放条 ↔ 播放页封面**（010）、**歌单 / 榜单卡片 ↔ 详情头部封面**（011）。
共同点是"同一张封面在两个界面里各有一份"，用户的眼睛希望它别跳。

## 方案 A（首选）：保留路由转场，只把封面交给覆盖层

路由转场（播放页 280 入 / 240 出 + 既有 spring；详情页右侧进入）是三轮真机验收的产物，
M10 不动它。共享元素只接管**封面这一层**：在两个界面之上放一个覆盖层，用同一个 key 把封面的
位置、尺寸与圆角从起点插值到终点，插值期间原地的两份封面各自隐藏。

理由：

- 两件事的责任不重叠——路由负责"页面怎么来"，覆盖层负责"这张图怎么过去"。把它们合成一套动画
  才是真正的耦合。
- 观感上，"封面飞过去"是用户能看懂的那一条线索；页面本身的位移反而是背景。
- 失败时退得回来：把覆盖层关掉，剩下的就是现在的转场，不会突然变得不能用。

具体约束：

- 共享元素的**实现库**：原计划用 `androidx.compose.animation` 里的设施。它此前只是 material3
  带进来的**传递依赖**，`v0.9.2` 已把 `androidx.compose.animation:animation` 显式声明进
  `implementation`（版本仍由 BOM 统一为 1.11.4），不引其它库。
- 时长取 large 档（350 / 450），乘 `LocalMotionScale`。系统动画缩放置 0 时**当帧到位**，
  不留中间态。
- 卡片端是 110dp / 96dp 的小图，播放页是 96dp 以上的大图，插值必须包含圆角
  （卡片与小图的圆角不同），否则中途会出现方角。
- 迷你条那一侧的封面有 4dp 级别的圆角与固定边长，端点位置要按实际测量取，不能按写死的常数。

## 落地修正（011 之后回看）

上面那四条"具体约束"有三条要改口，都记在这儿，免得下一个人按原文实现：

1. **没有用 `SharedTransitionLayout`**，用的是自写的覆盖层。那套 API 的前提是两端在同一次
   动画作用域里（`AnimatedVisibility` 或导航的 `AnimatedContentScope`）；本项目的迷你条是
   `Scaffold.bottomBar` 里的 `if (currentRoute != PLAYER)`，卡片与详情页头分属两条路由，
   硬接只会得到"从目标位置淡入"的半截效果。**设计没变**（覆盖层 + 两端登记 + 位置/尺寸/圆角
   插值），换掉的只是库；`animation` 那条显式依赖仍然留着，`AnimatedContent` 一类在用。
2. **端点不止两个，所以要有一张以身份为键的登记表**。010 是两个固定槽位，一个枚举就够；
   011 是"N 张卡片 ↔ 4 条详情路由"。键的规则是这一片真正的设计，三条都有代价：
   - **卡片端的键必须含来源页**。同一个歌单同时出现在首页推荐排与歌单广场上，只按目的地分键时
     "从首页进、退回首页"可能落到广场那张卡的旧矩形上，而广场根本不在栈里。
   - **按路由路径判同，不按封面 URL 判同**。同一条列表的卡片与页头可能各自拿到不同尺寸的地址
     （酷我推荐列表给 `img`、歌单详情给 `pic`），按 URL 判同会把该飞的判成不飞。
   - **两端各自从同一批路由 builder 推导键**，所以没有一个 id 需要从卡片传到页面。
     代价是"哪一页的页头就是本页封面"这份白名单必须只有一份（`LyraRoutes.coverPath`）。
3. **"110dp / 96dp 的小图"这句不准**，卡片封面是动态宽度的正方形（首页 110dp、广场随列宽、
   收藏行 48dp）。反而印证了第 4 条：端点矩形一律现量，一个尺寸都没写死。

还有一条 ADR 里没写、但落地时必须立的**性能规则**：端点靠 `onGloballyPositioned` 报矩形，
滚动时每个可见项每一帧都在报，所以登记表**必须是普通 Map、不能是快照状态**，隐身也必须用
绘制期读的 `graphicsLayer { alpha = }` 而不是组合期读的 `Modifier.alpha(value)`。
否则"滚一格 = 整页重组"、"起飞一次 = 转场首帧多重组一页卡"，正面撞上 `v0.9.2` 定的
两条 Jank 门槛。这条是共享元素在这个项目里的**入场费**，写在工单 011。

## 方案 B（预定退路）：fade-only

触发条件是"两套位移打架"——具体看两处现象：封面与容器在不同方向 / 不同缓动上移动，
或者覆盖层与路由位移叠成"封面飞两次"。出现任一条就切方案 B：

**路由转场期间封面不位移，只做交叉淡出**，起点与终点各自原地淡入淡出，覆盖层不参与。
这条比方案 A 弱（丢掉了"飞过去"这条线索），但它绝不会打架，而且比现在的硬切还是好。

退路必须**预先写下来**再开工：否则真出现打架时，人在压力下会倾向于"再调两小时参数"，
而不是切到一条已知可用的路。

## 后果

- 共享元素需要两端都能**稳定地**拿到同一张封面：图没加载完时不能开始插值，否则会插值一张占位图；
  两端都必须能吃"图还没到"这个状态（先不播共享元素）。
- 覆盖层要跨导航动画存活，因此它不能挂在任一页面里，得挂在 `NavHost` 外层。
  `v0.9.2` 里 `ThemeRippleOverlay` 已经踩过一次同类问题（覆盖层必须常驻在树上，原点才量得准），
  那条经验对这里同样适用。
- 为 010 与 011 各留一次**录屏取证**：中间帧截图取不到（`CHANGELOG.md:635` 同因）。
  011 落地后补一条：卡片 ↔ 页头那两端的封面走**网络取图**，模拟器有网就能加载真封面，
  所以去程与回程在模拟器上就判得了（`build/f011*.mp4` 三段）。010 仍然要真机——
  迷你条那块封面得真在播一首歌才存在。
- 预测式返回仍然不做：navigation-compose 2.9.6 没有相关 API（`v0.9.2` 已核实），
  共享元素不改变这个结论。
