# 迷你条换曲文字交替

**Blocked by**: 005（♥ 与播放/暂停状态形变，`AnimatedContent` 那条路子已经走通）

**主交互**：无匹配模式（普通实现）

## 目标

迷你播放条那两行"曲名 + 艺术家"在**换到另一首歌**时交替一次；同一首歌的播放 / 暂停、
封面到位、时长回来这些更新一个字都不动。M9 把"什么变化才配得上一次动画"定成了原则，
本片是它在迷你条上的落点。

## 涉及层

- [x] `ui/common/MiniSongLines.kt`（新）：`LyraSongLines(song, modifier, idleLabel, idleHint)` 组件、
  `SongLineText` 交替键、纯函数 `songLineText` / `songIdentity` / `artistLine`。
- [x] `ui/motion/LyraMotion.kt`：新增 `songLineSwap(scale)`（micro 档、行高五分之一的纵向位移、
  关掉动画时 `None togetherWith None`），常数 `SLIDE_FRACTION = 0.2f`。
- [x] `ui/LyraApp.kt`：`MiniPlayerBar` 里那两条 `Text` 收成一行 `LyraSongLines(...)`，
  顺手删掉因此不再使用的 `TextOverflow` import。
- [x] `SongLineTextTest`（9 条 JVM）、`SongLinesUiTest`（6 条设备断言）。

## 为什么"判据"必须是身份，而不是文字、也不是 Song

`AnimatedContent` 按 `targetState` 的 `equals` 决定要不要交替，所以**交替键的字段表就是这条规则的
可执行形式**。`SongLineText` 因此带三项：

- `(source, id)`：换一首同名同艺术家的歌照样交替。两行字一样但旁边封面同时换了，
  不动一下会读成"这一行还属于上一首"。`id` 只在单个音源内是主键，必须带上 `source`
  （与 `FavoritesRepository.keyOf` 的 `"$source:$id"` 同口径，UI 层不另发明一套身份）。
- 两行文字本身：万一某条路径把同一 `id` 的曲名改了（本地文件改标签后重新扫描），
  文字必须换过去，不能因为"身份没变"就停在旧字上。
- **不含 `Song` 本体**：封面、时长、清晰度这些字段陆续补上时两行字一模一样，
  重播一次交替是无信息噪声。播放状态也进不了这个键——`songLineText` 的入参里根本没有它。

快速连点切歌只往**最新那一首**交替：这是 `AnimatedContent` 自带的行为（新目标到来时取消上一次
未完成的交替），不要"顺手"改成排队播放——那会追不上手指，读起来是一段滚动字幕。

## 两处实现上的坑

### `using(null)` 不是可选的

`ContentTransform` 默认带一层 `SizeTransform`（用 spring 动画**容器尺寸**），而动画任何参与布局的
属性是 ADR-0009 护栏二明令禁止的。所以这里必须 `.using(null)`，与 005 的 `PlayPauseGlyph` 同一条理由。
`using` 是 `AnimatedContentTransitionScope` 的成员扩展，只能在 `transitionSpec` lambda 里调，
所以它留在调用处、没有收进 `LyraMotion.songLineSwap`——这不是风格不一致，是语言限制。

### 位移按行高算，不写死 dp

取五分之一行高（`initialOffsetY = { h -> (h * 0.2f).toInt() }`）。写死 6dp 的话，小字号档下
"几乎看不出来"、大字号档下"像整页在滚"；按比例则两个字号档的绝对位移都落在 4~6dp 这一档。

## 文案不在这里发明

`mini_player_idle` / `mini_player_idle_hint` / `mini_player_unknown_artist` 沿用现有字符串，
"没有艺术家不等于没在播"那条老规矩（正在播本地歌时不许显示"导入音源后即可播放"）
原样搬进 `artistLine`，并给了一条 JVM 测试钉住——那个 bug 曾经过一次，回归线得留在能跑的地方。

## 验收标准

- `SongLineTextTest` 9 条 JVM：同曲补元数据不重触发、同一输入重复调用给出同一个键（键里没藏状态）、
  同名同艺术家的另一首歌必须重触发、跨音源同数字 id 是两首歌、改标签后文字要换过去（且身份确实没变，
  证明"不相等"来自文字项）、空白艺术家落到"未知艺术家"、多位艺术家按 ` / ` 连接、
  未播放时两行都是 idle、以及 idle 与任何歌都不相等（否则播第一首那一次交替会丢）。
- `SongLinesUiTest` 6 条设备断言，判据是"屏幕上这份文字同时存在几份"（走 **unmerged** 语义树——
  合并树会把两处 `Text` 并进同一个节点，那时"交替进行中有两份内容"数出来还是 1，全部断言失去意义）：
  缩放 0 时换曲**第一帧**就只剩新曲名（`reducedMotionDropsTheOldCopyOnTheFirstFrame`）；
  同一首歌补元数据时**只有一份**（`metadataUpdateOnTheSameSongDoesNotSwap`，scale=1 下测，
  防的是"动画开着时误触发"）；连点两首最终只留最新那首
  （`rapidChangesOnlyLandOnTheNewestSong`）；容器尺寸不逐帧插值
  （`swapDoesNotRampTheContainerWidth`）；以及必需的**对照组**
  `realSongChangeKeepsBothCopiesWhileSwapping`——真换曲时交替中途旧、新两份都必须在场。
  没有这条对照，"只剩一份 / 零份"那几条完全可能只是因为 `AnimatedContent`
  把退场内容挡在语义树外，那样什么都没测。对照组在第 1 帧与第 2 帧各断一次"旧的还在"，
  其中第 1 帧与上面那条例外用**同一个帧位**相比：两条错开帧位比，差出来的就只是帧数而不是动画。
  第 6 条是像素差分而不是数份数：`reducedMotionNeverPaintsBothCopies` 判"关掉动画时任何一帧都不许
  同时画出两份文字"。它抓的是一个真实发生过的实现错误——以为 `None togetherWith None` 就是
  直接到终态，实测那一帧两份同画，迷你条会闪一下叠字。这条与 005 的同名像素测试是一对，
  因为 014 抄的就是 005 的写法，两处一起修（详见 CHANGELOG 的决策 8）。
- **护栏**：容器尺寸动画关掉（`using(null)`），且交替不许改变那一行的尺寸。这一条两头核实：
  **一头是量** —— `swapDoesNotRampTheContainerWidth`：交替进行中的 8 帧里，容器的宽与高必须逐帧一动不动
  （先断言两条曲名量出**不同宽度**，否则"没插值"可能只是"没东西可插值"）。
  **另一头是读源码** —— animation-android 1.12.1 的 `EnterExitTransition.kt`：slide 走
  `placeWithLayer(x, y, 0f, layerBlock)`，容器上报给父级的是 `layout(currentSize.width, currentSize.height)`，
  **不含 slide 位移**——纵向位移只挪绘制层，所以那一行的高度不会被交替撑大。
  两头各管一件事：源码那次只回答"库不会这么干"，而 `.using(null)` 到底有没有生效只有量得出来。
  迷你条其余部分（封面、按钮、点击区）本片一个都没改。
- 依赖：一条都没加。`androidx.compose.animation:animation` 早在 010 就已显式声明。
- **真机录屏已补**（PLK110 release，音乐库页，`build/walk/p/swap2.mp4`，逐帧在
  `build/walk/p/swap2/`）。**录到了哪一屏要说清**：只有音乐库那一段有迷你条；
  同批的 `swap.mp4` 是播放页，那一屏根本没有迷你条，量不到本片。
- **抓到两次换曲**（爱不释手 / 李丽芬 → 渡千关 / 文雯 → 宠爱我吖 / 白小白·球球），
  逐帧差分（区域 = 迷你条两行字，阈值：单像素 RGB 三通道差之和 > 40、单行 > 3 个像素）：
  第一次 f0004–f0009 有变化、f0003 与 f0010 两侧零变化；第二次 f0018–f0022 有变化、
  f0017 与 f0023 零变化。录像的真实时间戳取自 `ffprobe`（变帧率，不能按帧号乘 fps）。
  于是时长只能夹在两个数之间：**第一次 ∈ (83ms, 133ms]、第二次 ∈ (66ms, 100ms]**。
- **为什么不给一个点值**：这段录像的帧间隔 ≈16.4ms（60fps），±17ms 是它的分辨率下限，
  **100ms 与 120ms 本来就分不开**。能下的结论只有"落在 micro 档
  （进入 100 / 退出 120）"这一条。先前写的"约 116ms"是循环论证——那个数就是我挑的
  帧区间的跨度本身，不是量出来的时长，作废。
- **方向与交叉淡出逐帧看过**（`build/ps/swap2_dir.png`，f0003–f0009 竖排）：新字从下方进来
  （f0004 上新字整体低于旧字一行），旧字向上退出，两行同时在场 4~5 帧。与
  `songLineSwap` 的 `+0.2h → 0` / `0 → −0.2h` 一致；这一段是**看过**，不是推导。
- 录像里**没有**暂停 / 恢复事件——两次换曲之间（f0010–f0017，约 3 秒）整条迷你条零变化。
  所以"同曲改播放态不动文字"**不由这段录像证明**，判据只有设备测试
  `metadataUpdateOnTheSameSongDoesNotSwap`（模拟器）与 `SongLineTextTest` 的 JVM 断言。
