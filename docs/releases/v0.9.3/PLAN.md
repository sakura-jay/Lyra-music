# Lyra M10 = v0.9.3 计划（播放连续性）

> **状态：010–014 全部落地（代码 + 测试 + 真机逐片录屏）。** 本文件是 `v0.9.2` 收口时按已排定的优先级
> 写下的计划，切片编号接 M9 的 009。决策见 [`../../adr/0010-共享元素转场.md`](../../adr/0010-共享元素转场.md)。
> 术语以 `CONTEXT.md` 为准（"共享元素"一词由 `v0.9.2` 写入）。
> 实现记录见 [`tickets/`](tickets/)，逐片实现提示词见 [`PROMPTS.md`](PROMPTS.md)
> （010–014 五段都是实现之后补写的，与代码一致，可当 review 依据）。

M9 让动效"有语言"，M10 让**播放这件事本身连续**：从哪张封面点的，封面就飞到哪去；
在迷你条上换歌，文字换而不是整条重画；拖 seek 松手时，手指的速度决定落在哪一秒。

## 2. 逐片要点

### 010 / 011 共享元素封面

按 ADR-0010 的方案 A：路由转场数值不动，封面这一层交给 `NavHost` 外层的覆盖层做位置、尺寸、
圆角插值，时长走 large 档（350 / 450）× `LocalMotionScale`。两处共同的硬约束：

- 图没到就不开始插值（不能插值一张占位图）；
- 圆角必须一起插值（卡片圆角 ≠ 大图圆角）；
- 覆盖层挂在 `NavHost` 外面（它要跨导航动画存活）；
- 系统动画缩放置 0 时当帧到位。

011 落地时把这套设施从"两个固定端点"泛化成**以封面身份为键的端点登记表**，并补了三条计划里
没写的硬约束：卡片端的键含来源页、登记表不可观察、终点矩形现量。逐条理由与实测证据在
[`tickets/011-歌单与榜单卡片与详情页头封面共享.md`](tickets/011-歌单与榜单卡片与详情页头封面共享.md)，
决策追记进 ADR-0010。原先那句"卡片是 110dp / 96dp 的小图"不准：卡片封面是**动态宽度的正方形**
（首页 110dp、两个广场随网格列宽、收藏行 48dp），所以端点矩形一律现量，一个尺寸都没写成常数——
这正是 ADR 里"不能按写死的常数"那条的兑现。

### 012 pager 视差（已落地，两处与计划不同）

006 只接了 `currentPage`，页码跟手与封面视差都留给本片：翻页过程中封面按
`currentPageOffsetFraction` 做小幅平移（**只走 `graphicsLayer`**），页码指示器跟随拖动而不是
翻完才跳。落地后与计划有两处出入，都记在 [`tickets/012-翻页跟手与封面视差.md`](tickets/012-翻页跟手与封面视差.md)：

- **视差量不是真机定的**：它被两条界夹出来——封面自身的横向余量（约 45dp）给上界，
  JVM 那条 `parallaxStaysSmallEnoughToReadAsDepth` 把常数夹在页宽 5%–12%（满程）与 ≤ 8%（中点）。
  真机目视因此只判"好不好看"，不兼"选一个数"。
- **歌词页不给视差**（计划里留了"可以更小一档"的余地）：那一页唯一要读的就是字，
  文字以另一个速度漂读到的是"字在晃"；整页一起位移则因为滚动视口高度不变，深度感为零。

另外加了一条计划里没写的设计判断：**几何跟手、身份跳变**——宽度与让位每帧现算，
颜色仍由离散的 `currentPage` 驱动。

### 013 seek 惯性吸附（模式 4，已落地，两处与计划不同）

**这是全项目唯一一处真正的 Velocity-Based Slider Snap**，所以在 M9 判定"无匹配（留 M10）"。

行为：松手时用释放速度投影一个落点（上限 ±3s），把滑块**与播放位置**一起 `seekTo` 到那个值——
**过冲即真实落点**，不做"弹回来"的假动作；`reduced-motion`（缩放置 0）时跳过投影，直接落在手指处。

可测的那一半抽成纯函数 `SeekInertia`，JVM 单测覆盖速度窗口与 clamp 边界；"这一下是不是手指松的"
在 `SeekDragState`——它自己看 Initial pass，不用 `SliderState.isDragging`，因为那个标志位在
`onValueChangeFinished` 之前就被 `drag()` 清掉了（material3 1.4.0 自己的注释说的就是这件事）。

落地后与计划有两处出入，理由与源码证据都在
[`tickets/013-seek惯性吸附.md`](tickets/013-seek惯性吸附.md)：

- **不做拇指按压放大**：M3 1.4.0 的默认拇指是 4dp × 44dp 的竖条，按下时它自己就窄到 2dp，
  再叠一层 1.12 缩放是 0.45dp 的变化——看不见，还与库打架。气泡才是有效反馈。
- **读屏播报手指处而不是投影落点**（原提示词要求后者）：投影值每帧都在变，做成 live region 会让
  TalkBack 在拖动途中反复播报。落点本身对无障碍路径**不受投影影响**，这条用恰好 15000ms 钉住。

另外有一个**计划里没有、实现里却决定成败的常数**：`CARRY_MS`（偏移 = 释放速度 x 它）。
先写成 120 时，±3s 上限在慢吞吞拖动时就 bind，于是"任何一次拖动都正好跳 3 秒"——模式 4 的
分级（甩得快跳得远）退化成一个开关。改成 12 之后上限只在约 1 px/ms 处碰得到，并有一条
"不同速度必须给出不同偏移"的 JVM 测试当护栏。

### 014 迷你条换曲文字（已落地，取证方式与计划不同）

只有**换曲**时文字才动（`AnimatedContent`，micro 档）；同一首歌的播放 / 暂停状态变化不动文字。
否则暂停一下标题就重播一次动画，噪声大于信息。

计划里写的取证是"截图"，**实际没用截图**：这一片要判的是"什么变化配得上一次交替"，
那个判据在语义树上直接数得出来（交替进行中共有两份文字、没发生时只有一份），
比截图稳，也不依赖字体度量。截图能证明的只有"最后停在哪个字上"，那正是最不需要测的部分。

一处与 ADR-0009 相关的实测修正：`EnterTransition.None togetherWith ExitTransition.None`
并**不等于**"直接到终态"——它仍会把旧、新两份内容同画一帧。这一档因此改成
"关掉动画时压根不进 `AnimatedContent`"，换曲时第一帧就只剩新曲名。
同一条错误也在 005 的播放/暂停图标上，两处一起修；像素差分的回归测试各一条
（[`CHANGELOG.md`](CHANGELOG.md) 的决策 8）。

按同一条判据（**关掉动画时不许读动画值**）回头扫本版所有落点，又多抓到两处：005 的 ♥
交叉淡出（1525px，`snap()` 也救不了）与 006 / 012 页码指示器的**颜色**（1130px，
形状本来就没问题，颜色是 `animateColorAsState`）。两处都修成"关掉动画就直接取终值"，
各由一条像素测试钉住。歌词换行的强调值同族且**原本连缩放都不读**，一并接入层级换算，
但那一处没量（换行同时列表在滚，像素相减分不开），按"未量"记账而不是"已测"。

## 3. 完成长什么样

- 与 M9 同一套回归线：编译 + JVM 单测 + instrumented 全量绿，`lintDebug` 0 error。
  **已达成**：JVM 137 条、instrumented 172 条 `OK`（`emulator-5554`）、lint 0 error / 6 warning。
- 011 三段模拟器录屏已交（`build/f011*.mp4`）。010 原写"只能真机录，因为模拟器没有音源"，
  **那句是错的**：酷我源在模拟器上能播、迷你条有真封面，来回六趟录到了封面飞行的中间帧
  （`build/walk/f010b.mp4`，拼图 `build/walk/sheet/f010b_big.png`）。真机那一段只补"顺不顺"，
  因为模拟器 `screenrecord` 只有约 2.8 有效 fps（13.04s / 46 帧）。
- 012 的中间帧由像素级 ui 测试负责。原本写的理由"`screenrecord` 每帧字节相同"也不准，
  真实理由是**帧率**：一帧约 700ms，而本片是跟手拖动，`input swipe` 那 400ms 里手指与页面都在动，
  抽到的那一帧不代表"拖到一半"。013 同理：惯性落点有设备测试钉，观感仍要真机录屏；
  014 的判据走语义树计数而不是截图（见上）。
- Jank 门槛不变：**滚动 + 转场首帧** < 1%，微交互不参与考核。
- M10 是 M9 首帧 jank 收口的直接受益者：若 001 的结论是"120Hz 首帧不可达标"，
  本片的共享元素仍按 60Hz 稳态验收。

## 4. 明确不做

沿用 M9 的"明确不做"清单：播放队列 UI、手势拖拽展开 / 收起播放页、预测式返回转场、
滑动删除 / 拖拽排序、逐字歌词渐变软边。其中队列 UI 不做意味着**卡片堆叠滚动**与
**拖拽排序**依旧无落点，本版同样不为它们预留接口。
