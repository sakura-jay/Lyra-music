# 020 骨架修正（歌单详情补落点 / 整行形状 / shimmer 可见）

## 问题（用户视频 + 文字反馈）

1. **歌单详情没有骨架**：018 的四处落点不含 `TrackListScreen`（歌单/专辑/榜单外的
   自建歌单与本地歌单走它），加载时只有页头一个小转圈 + 全页空白——"骨架位置不对
   覆盖不全"指的就是这一页。
2. **行骨架前置 44dp 方块太突兀**：`TrackRow`（榜单行：序号+标题+副行+♥/菜单）与
   `SongRow`（搜索结果卡：标题+副行+来源）都是**纯文字行**，没有图片；给它们配
   "方块+两行字"的图片行骨架，形状对不上。
3. **shimmer 没有动画感**：018 版 highlight 取 `surfaceContainer`，在浅色主题里
   比底色 `surfaceContainerHigh` 更深，加上 1.0 步长的宽渐变带，扫光肉眼不可辨
   （用户原话"没有骨架的加载动画，只有骨架"）。

## 修法

- `TrackListScreen`：`state.loading && list == null` 时给 8 行 `LyraSkeletonRankRow`
  （序号条 26×24dp + 两行字 + 右侧 16dp 小点，与真实行同构），沿用 40ms 错峰 cap 240ms。
- `LyraSkeletonListRow` 拆成两个：`LyraSkeletonRankRow`（带序号条，榜单用）与
  `LyraSkeletonTextRow`（纯两行字，搜索用）；44dp 方块删除。
- `LyraSkeleton` 高光按底色亮度推导：`luminance > 0.5` 往白推 65%，否则推 16%；
  渐变带收紧到 0.5 步长（`start=phase*1500`，`end=(phase+0.5)*1500`）。
  两个主题里扫光都是一道亮带。

## 验收

- JVM：`highlightIsBrighterThanBaseInBothThemes`。
- 模拟器截图：榜单详情加载态 8 行整行形状（无突兀方块），数据到达后原位替换；
  shimmer 相邻两帧差分显著（此前不可辨）。
- 真机目视四处落点。

## 不做

- 不引第三方；不做 shimmer 速度分级；不给骨架加交叉淡出。
