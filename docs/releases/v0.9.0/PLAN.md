# Lyra M8 = v0.9.0 计划与规格

> 本文件是本版的**规格说明书与切片计划**。结果记录见同目录 `CHANGELOG.md`。
> 术语以 `CONTEXT.md` 为准；本版新增术语（我喜欢 / 收藏的歌单 / 榜单 / 榜单广场 / 开发分支）已写入。
> 版本与文档约定：`main` 上只留一条该版本记录；开发在 `dev/v0.9.0` 上按切片提交。

---

## 1. 问题陈述

M7 收口后，三处现状与"可长期自用"的目标有距离：

1. **我喜欢与音乐库其余部分混在一起。** `LibraryScreen` 把已收藏的单曲做成内联长列表放在最上方（`LibraryScreen.kt:100-138`）。收藏一多，我的歌单 / 收藏的歌单 / 本地音乐三段被挤到屏幕之外，想找自建歌单要先划过几百行单曲。
2. **缓存上限写死。** `LyraCache.MAX_BYTES = 128MB` 是常量，直接喂给 `LeastRecentlyUsedCacheEvictor`（`LyraCache.kt:33,42`）。用户既改不了，超限也没得商量——设置页只能显示这个数字。
3. **榜单只有一家、布局是拍平长列表。** 榜单数据来自唯一的内置酷我适配器（`KuwoLeaderboardProvider`），首页用"吸顶芯片换榜 + 拍平曲目列表"。多来源无从体现，榜单之间也没有可浏览的全景。

---

## 2. 方案概述

- **我喜欢独立成页**：音乐库顶部放一张卡片入口「我喜欢 · N 首」，点进独立的曲目列表页；库内不再内联单曲。
- **缓存上限可调**：缓存详情页顶部提供预设档位芯片与自定义滑块；上限运行时生效，调低立即淘汰（ADR-0008：自定义 evictor，不重建 `SimpleCache`）。
- **榜单多来源 + 榜单广场**：新增内置酷狗、网易云榜单适配器；新建「榜单广场」页按来源分段罗列全部榜单卡片，点卡片进详情；首页保留一行精选预览 + 「更多」。
- **版本与文档**：M8 = `0.9.0`；每版本一个目录（本目录），根 `CHANGELOG.md` 退化为总索引；`1.0` 留给最终收口里程碑。

## 3. 用户故事

### A. 我喜欢独立成页

- **A1** 进音乐库，最上方是一张卡片入口，显示「我喜欢 · N 首」（N 为当前收藏数）；收藏为 0 时显示空态引导，不显示卡片计数为 0 的怪异态。
- **A2** 点该卡片进入「我喜欢」页；该页是曲目列表：头部为标题「我喜欢」+ 曲目总数，下面是全部已收藏曲目。
- **A3** 在「我喜欢」页点任意一行 → 播放该曲，播放队列 = 整个我喜欢列表（顺序同页面显示顺序，即收藏时间倒序）。
- **A4** 在「我喜欢」页点某行的 ♥ → 该曲移出我喜欢；列表与音乐库入口的计数当场更新，不移出页面。
- **A5** 在「我喜欢」页点某行的「更多操作」（行尾 ⋯）→ 打开"放去哪儿"选择器，可加入自建歌单或做单曲操作（沿用应用级 `PlaylistPickerViewModel`）。
- **A6** 音乐库段落顺序为：我喜欢（卡片）→ 我的歌单 → 收藏的歌单 → 本地音乐。收藏的歌单不拆页，仍内联。
- **A7** 全应用文案中，歌曲入库一律叫「我喜欢 / 加入我喜欢 / 已移出我喜欢」；歌单入库仍叫「收藏 / 收藏的歌单」。空态、提示、播放页 ♥ 的读屏标签同步改。

### B. 缓存上限可调

- **B1** 进缓存详情页，顶部有「上限」段：一组预设芯片（128MB / 256MB / 512MB / 1GB / 2GB），以及一个「自定义」滑块（范围 64MB–4GB）。
- **B2** 当前上限对应的芯片呈选中态；上限为预设以外的值时，「自定义」呈选中且滑块停在对应位置。
- **B3** 上限值持久化（`AppSettings` / SharedPreferences），重开应用后保持。
- **B4** 把上限调低到当前占用以下（例：已用 300MB，上限调到 128MB）→ 立即按最久未听淘汰到新上限，页面总字节与条数当场变小，并提示「已释放 X」。
- **B5** 把上限调高不触发任何删除。
- **B6** 设置页「存储」段那行上限数字（`settings_cache` 文案里的 `%2$d MB`）显示为当前上限，不再硬编码 128。
- **B7** 上限变更不影响正在播放的曲目（播放不断流）。

### C. 榜单多来源 + 榜单广场

- **C1** 首页在"推荐歌单"下方新增一行「榜单」区：横滑展示若干精选榜卡片 + 右侧「更多」。
- **C2** 点首页「榜单」区的「更多」→ 进入「榜单广场」页。
- **C3** 榜单广场按来源分段（酷我 / 酷狗 / 网易云），每段一个来源标题，段内以网格排开该来源的**全部**榜单卡片。
- **C4** 每张榜卡片有封面图；取不到图时用占位（纯色 + 榜名），不出现破图空白。
- **C5** 点任意榜卡片 → 进入该榜的曲目列表页：**头部**（榜名 + 总数 + 榜封面）+ 带序号的曲目行。
  （**更正**：原先写"复用 `TrackListScreen`"做不到——它是一次性取数、无分页，而榜有 100–300 首；
  分页状态机要从首页那套抽出来给详情页用，见工单 009。）
- **C6** 榜单列表支持触底分页（沿用现有 100 首/页的状态机）；切榜丢弃晚到的响应，标题与列表不串。
- **C7** 某个来源的榜单取数失败时，只有该段呈现错误/空态，其余来源段不受影响。
- **C8** 榜单卡片网格滚动流畅：不因封面图加载而掉帧（见 D）。

### D. 榜单封面图片性能

- **D1** 榜单广场滚动过程中，同一张封面不因滚出再滚回而重复解码（需有解码位图缓存，当前 `rememberRemoteArtwork` 无）。
- **D2** 同一 URL 的并发请求被去重（一次网络下载，多处共用）。
- **D3** 封面按卡片尺寸降采样（`decodeDownsampled`），不把原图整张塞进内存。
- **D4** 榜单广场滚动 Jank 率 < 1%（沿用歌词页标准，`gfxinfo framestats` 新指标），与歌单广场/曲目列表同一量级。

## 4. 已定决策

- **术语**：歌曲 = 我喜欢；歌单 = 收藏的歌单；按 kw/kg/wy 分组这一层沿用「来源」，不引入「平台」；榜单 / 榜单广场 已入 `CONTEXT.md`。
- **代码标识符不改名**：`FavoritesRepository`、`library_favorite` 等保持不动，只改 UI 文案与 `CONTEXT.md`（避免大范围无谓改动）。
- **我喜欢页复用** `TrackListScreen` / `TrackListViewModel`，不新开页面形状。
- **缓存上限实现**：自定义 `CacheEvictor`（读可变上限），不重建 `SimpleCache` —— 见 ADR-0008。
- **缓存上限默认 128MB**；档位 128/256/512MB、1/2GB；自定义滑块 64MB–4GB。
- **榜单来源**：酷我 + 酷狗 + 网易云，**均走内置适配器**（循 ADR-0003：音源未实现 `leaderboard` 时由内置提供）。本版不为榜单开音源通道。
- **榜单分页** 沿用现有 PAGE_SIZE = 100（服务端单页上限）。
- **版本**：M8 = `0.9.0`；一期保持"一里程碑一 minor"；`1.0` 为终点里程碑，不随自然号推进。
- **文档结构**：每版本一个目录 `docs/releases/vX.Y.Z/`，内含 `PLAN.md` + `CHANGELOG.md`；根 `CHANGELOG.md` 转为总索引。
- **Git**：开发在版本级开发分支 `dev/v0.9.0`；切片在其中按功能提交；合回 `main` 时整体 squash，`main` 上只留一条 `v0.9.0` 记录。已同步写入 `CONTEXT.md`。
- **验收补充（2026-10-12，工单 012）**：音乐库**四段全部做成入口卡片**（我喜欢 / 我的歌单 / 收藏的歌单 / 本地音乐），因此新增「我的歌单」「收藏的歌单」两个列表页；「我喜欢」页与卡片的封面取**最近添加那一首**（列表按 `added_at DESC`，即第一行）。

## 5. 测试决策

接缝优先级：能复用既有接缝就不新建；让每个切片尽量只跨一个接缝。

- **我喜欢页**：复用 `TrackListScreen` / `TrackListViewModel` 这一既有接缝（专辑/平台歌单/自建歌单/本地音乐已共用）。`loader` 是注入的 lambda，页面状态可测；取消收藏后的列表刷新沿用 `MyPlaylistRoute` 的"观察仓库计数变化 → reload"模式。
  - 设备测试：取消收藏一行后，行消失且音乐库入口计数 -1。
- **榜单广场与首页榜单区**：沿用 `HomeViewModel` 的 `fetchBoard: suspend (Board, Int, Int) -> BoardPage` lambda 模式，把取数注入 VM。**分段/分页/切来源丢弃晚到响应**这套状态机在纯 JVM 上测（对照既有 `ui/home/HomePagingTest`）。
  - 设备测试：酷狗、网易云榜单打真实端点各返回非空（对照既有 `KuwoLeaderboardProviderTest`）。
- **缓存上限**：自定义 evictor 的 LRU 与淘汰逻辑**不依赖 Android**，纯 JVM 单测覆盖（上限读值、超限淘汰顺序、调低即淘汰到上限）。`LyraCache` 的上限变更与在播不断流放设备测试（对照既有 `LyraCacheTest`）。
- **榜单封面图片**：缓存/去重/降采样收敛到 `ArtworkLoader` 一处接缝，设备侧测（去重、命中）。
- **仪器化测试一律走独立数据库**（工单 013，真机验收时补的硬约束）：`FavoritesDatabase` 收一个可选
  库名，测试全部传 `lyra-library-test.db`，测试代码里不得再出现生产库名 `lyra-library.db`。
  原因：四个仓库测试靠 `deleteDatabase()` 断言持久化，用默认库名等于**在真机上跑一次套件就清空用户的
  收藏、自建歌单与收藏的歌单**。这条是"完成长什么样"的一部分，不是可选清理。
- **"完成"长什么样**：
  - 全量 instrumented tests 在 Pixel_8 模拟器通过；release 前在真机 PLK110 跑一遍回归。
  - 榜单广场滚动 Jank < 1%（`gfxinfo framestats` 新指标）。
  - `:app:lintDebug` 0 error。

## 6. 明确不做

- **榜单不开音源通道**（内置适配器优先，循 ADR-0003）；本版不引入 QQ 音乐 / 咪咕。
- **我喜欢不做**排序、筛选、批量编辑。
- **缓存不做**「不缓存 / 无上限」档，也不与下载管理合并。
- **代码标识符不改名**（见"已定决策"）。
- 歌手页、评论区、悬浮歌词、桌面小组件、多端同步等仍属二期（见根 `CHANGELOG.md` 的「明确不做」）。

- **技术提示**：
  - 榜单广场是"网格套在可滚动页里"。避免嵌套滚动容器：要么整页用 `LazyVerticalGrid`（来源标题作为横跨整行的 header item），要么段内用非滚动的 `FlowRow`，二选一，不要 `LazyColumn` 里再套 `LazyVerticalGrid`。
  - `TrackListScreen` 现只支持顶部整列表收藏（平台歌单用），不支持行内 ♥。我喜欢页需要行内 ♥（点=移出），要给 `TrackListScreen`/`TrackRow` 加一个"行内收藏"转发口，别在页面里另写一份行。`TrackRow` 已支持 `favorite` + `onToggleFavorite`（`TrackRow.kt:53-54,117-126`），主要是把参数从 `TrackListScreen` 透下去。
  - 榜单卡片的封面是新的数据依赖，且**两家给的形状不一样**：酷我没有"榜列表"接口（`api/bd/bang/bang_list` 路由存在但参数一律 `PARAM_ERROR`；lx 也只有静态表），封面只随 `bang_info` 的 `data.pic` 带回，12 张榜已逐张实测非空；酷狗有 `v5/rank/list`（28 张榜带 `img_9`），但它的 `id`/`rank_cid` 与 `rank/song` 认的短 `bangid` 不是一套，按榜名配对不稳，故改用**榜首歌曲的专辑图**充当。统一约定：`Board.coverUrl` 静态表里留空，**带图那份一律由 `songs()` 返回的 board 给出**，取不到用图标占位——榜单广场因此必须懒加载这些轻请求。
