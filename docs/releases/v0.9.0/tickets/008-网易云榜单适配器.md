## 前置情报（2026-10-12 已从 lx 读到确切实现，未开工）

来源：`lyswhut/lx-music-mobile` `src/utils/musicSdk/wy/leaderboard.js` + `wy/utils/crypto.js`。

**榜表**：`topList` 是**歌单 id**（网易云的榜就是歌单），短表可取
`19723756 飙升榜 / 3779629 新歌榜 / 2884035 原创榜 / 3778678 热歌榜 / 991319590 说唱榜 /
71384707 古典榜 / 1978921795 电音榜 / 71385702 ACG榜 / 745956260 韩语榜 / 5059661515 民谣榜`
（lx 全表 40+ 条，其中"编辑推荐榜VOL.44 …"那种带期刊号的长名不适合当静态表）。

**取数要两次调用**（这是它比酷狗重的主要原因）：
1. `POST https://music.163.com/weapi/v3/playlist/detail`，body `{id, n: 100000, p: 1}`
   → 只给 `playlist.trackIds[]`，**不给曲目详情**；
2. 再用 `wy/musicDetail` 拿 id 对应的 `Song` 对象。

**weapi 加密**（**最终没用到**，见下一节；记在这里是因为若明文端点哪天失效，这是 lx 的备用路线）。
Kotlin 侧要实现的一组：
- `text = JSON.stringify(body)`
- 第一层：AES-128-**CBC**/PKCS7，key=`0CoJUm6Qyw8W8jud`、iv=`0102030405060708` → base64
- `secretKey` = 16 位随机数字串
- 第二层：同上 AES-CBC，key=`secretKey` → `params`
- `encSecKey` = 把 `secretKey` **反转**后做**无填充 RSA**（公钥 PEM 见 lx `crypto.js`，
  modulus 1024bit、e=65537），输出 256 位十六进制。
  Kotlin/Android 的 `Cipher("RSA/ECB/...")` 没有 NO_PADDING，得用 `BigInteger.modPow` 手写模幂。
- 请求 Content-Type：`application/x-www-form-urlencoded`，body 为 `params=&encSecKey=`。

**当时待验证**：weapi 是否从本机 IP / 无 cookie 可用；有没有更轻的公开替代。→ 结论见下。

## 结论：不用 weapi，两个明文端点够了（2026-10-12 实测）

1. `GET https://music.163.com/api/v6/playlist/detail?id=<榜id>&n=100000&s=0`
   → `code=200`，给 `playlist.name` / `playlist.coverImgUrl`（**榜封面在这**，比酷我还省事）/
   `playlist.trackIds[].id` / `trackCount`。实测热歌榜 3778678 返回 **200 个 id**。
2. `GET https://music.163.com/api/v3/song/detail?c=[{"id":287398},…]`
   → `code=200`，`songs[]` 含 `name` / `ar[].name` / `al.id`、`al.name`、`al.picUrl` /
   `dt`（**毫秒**）/ `l`、`m`、`h`、`sq`、`hr`（各带 `br`+`size`）/ `fee`、`st`。
   `c` 数组实测**一次 100 个 id 全回**。

## 实现记录（2026-10-12）

- `NetEaseLeaderboardProvider`：`v6/playlist/detail` 读榜，按页切 id，再 `v3/song/detail` 补详情。
  榜目录按 `board.id` 缓存，**第一页总是重读**——适配器是常驻单例，不重读则"重载"拿不到新榜；
  翻页复用缓存，不让每一页都重拉 200 个 id。
- **档位**：只收 Lyra 认的四档，`l`→128k、`h`→320k、**`sq`→flac、`hr`→flac24bit**
  （先前记的"明文端点未见无损字段"是错的，实测 `sq`/`hr` 就在响应里）。`m` 的 **192k 没有对应档位，直接不收**：
  硬标成 320k 等于让音源拿 192k 的文件去交 320k 的差。无会员/下架的歌这些桶可能是 0 字节，
  按 `size > 0` 过滤就不会写出根本不存在的档位。
- **12 张榜逐张实测**：`code=200`、`trackCount` 50–200、封面齐、详情可取。其中 `3812895` 是
  **Beatport 全球电子舞曲榜**（先前误标成"影视金曲榜"，已纠正为实测过的国风榜）。
  lx 表里"编辑推荐榜VOL.44 …"那种带期刊号的长名不适合做静态表，没收。
- 网易云的"榜"就是歌单，`bangId` 存歌单 id。已注册进 `ServiceLocator.leaderboardProviders()`（三家齐）；
  新增设备测试 `NetEaseLeaderboardProviderTest`（含档位合法、翻页不重叠、封面断言）。
- **播放可达性**：内置适配器本就不给 `musicUrl`，酷我/酷狗的榜歌也靠用户音源取址，网易云同构；
  但**音源不支持 wy 时，榜上的网易云歌播不出来**——发版说明要写清这条。
