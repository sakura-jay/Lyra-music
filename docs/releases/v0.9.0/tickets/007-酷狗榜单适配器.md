## 目标
内置酷狗榜单：能按榜取到曲目（含分页），字段映射复用酷狗已有的搜索 / 歌词适配器。

- [ ] 逻辑层：注册进榜单来源目录。
- [ ] UI 层：无。
- [ ] 测试：设备测试——真实端点各返回非空；分页到 total 停止；字段（曲名 / 歌手 / 时长 / 音质）正确。

## 验收标准
- 酷狗榜单可列出榜列表与曲目，实测非空。
- 签名 / 端点以真机实测为准（不照抄 lx）；踩坑记入注释 / changelog。
- 分页行为与酷我一致（单页上限、到 total 停）。

## 破解记录（2026-10-12 第二轮，按"先查 lx"的规矩读到确切参数）

之前失败的根因是**参数组合**：我用 v1161 + v3 `rank_cid`（131010 那批）。lx 的确切写法是
`version=9108` + `rankid=<bangid>`（8888/6666 那一套**短 bangid**，与 `rank/list` 给的
`id`/`rank_cid` 都不是同一套）+ `with_res_tag=0&show_portrait_mv=1`。实测：

- `rank/song?...&rankid=8888&version=9108&ranktype=1&plat=0&area_code=1&with_res_tag=0&show_portrait_mv=1&pagesize=30&page=1`
  → **total=500，单页 30 首**；`page=2` 与 `page=1` 零重叠。
- 条目字段：`audio_id`（当 `Song.id`）/ `album_audio_id` / `songname` / `authors[].author_name` /
  `album_id` / `album_name` / `duration` / `album_sizable_cover`（带 `{size}`）。
- 档位是**四组独立 hash+size**：`hash`+`filesize`、`320hash`+`320filesize`、
  `sqhash`+`sqfilesize`、`hash_high`+`filesize_high`（与搜索那套 `FileHash/HQFileHash/…` 键名不同）。
- 错误标志键是 **`errcode`**，不是搜索用的 `error_code`。
- 榜级图片 `rank/song` 不给（`data` 只有 `timestamp/total/info`）→ **用榜首歌曲的专辑图当榜封面**。
  `api/v5/rank/list` 有 `img_9`，但它的 `id`/`rank_cid` 与 `rank/song` 认的 `rankid` 不是一套，
  按榜名配对不稳，先不引（已记入适配器注释）。
- `http://` 明文端点：沿用 M1 已放开的 base-config，不另外加白名单。
