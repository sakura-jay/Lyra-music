# 仓库测试改用独立数据库，不再碰生产库

**Blocked by**: 无（真机验收时发现的安全问题，随本版一起收口）

## 目标
`connectedDebugAndroidTest` 在任何设备上跑都**不再可能删掉用户的收藏与歌单**，
测试仍然照常断言持久化。

## 背景
四个测试（`FavoritesRepositoryTest`、`PlaylistRepositoryTest`、
`FavoritePlaylistRepositoryTest`、`LibraryBackupTest`）用 `FavoritesDatabase(context)`
打开的是生产库 `lyra-library.db`，并用 `deleteDatabase()` 删文件来验证"重新打开还在不在"。
在真机跑一次 = 清空用户资产。

## 涉及层
- [x] 数据层：`FavoritesDatabase` 增可选 `databaseName`（默认仍是生产库，生产行为不变）。
- [x] 测试层：新增 `TestData.kt` 提供 `TEST_DB_NAME = "lyra-library-test.db"`；
      四个测试的所有 `FavoritesDatabase(...)` 与 `getDatabasePath(...)` 全部改指测试库。
- [x] 验证：`grep` 确认 `"lyra-library.db"` 不再出现在 `app/src/androidTest/`；
      模拟器实跑这四个类，全绿。

## 验收标准
- 生产库名在 androidTest 源码中零引用。
- 四个测试类在模拟器上通过（它们删的是测试库文件）。
- 生产代码路径不传库名时行为与改前完全一致。
