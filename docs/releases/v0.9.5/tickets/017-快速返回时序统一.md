# 017 快速返回时序统一（封面飞行 × 页面收起）

## 问题

点迷你条（或任何带封面卡片的入口）后**迅速返回**：封面已经飞回去，页面还在收、
甚至途中卡一下。每个带图片的界面都有。

## 根因（结构性读码，未量帧）

1. **两条时间轴**：回程封面 450ms（LARGE 档出值，`CoverFlight.kt` 的 `CoverFlightOverlay`）
   vs 页面收起 240ms（ROUTE 档，`collapseToBar`）。封面先到、页面后到。
2. **中断冻结**：`begin()` 要求上一场飞完（`animateTo` 挂起中，`LaunchedEffect` 不放行），
   快速往返时新导航触发的飞行被挡住，旧飞行继续往旧终点飞——用户看见的是封面僵在半路。
3. 触发统一走 `LyraApp.kt` 的 `LaunchedEffect(currentRoute)`，修一处全覆盖。

## 修法

- `CoverFlightOverlay` 时长改 `MotionTier.ROUTE`（280 入 / 240 出）× MotionScale。
- `begin()` 接力：飞行进行中再次触发 → 取消旧 job、清 flight/landing/landingKey、
  按新方向重起。旧 `RunningFlight.job` 由覆盖层 `attachJob` 挂入。
- 回程曲线保留 016 验收的 `FastOutSlowIn`（减速落位），页面收起保持加速离场。

## 验收

- JVM：`flightDurationFollowsRouteTierNotLarge` 钉 280/240，防改回 LARGE。
- 模拟器 instrumented 全量回归绿（真机装 release 包，不装 debug 测试包）。
- 真机 PLK110（release 0.9.5 / versionCode 10，同签名升级）两轮录屏逐帧：
  - **慢速往返**（`build/ps/a017d.ps1`，进详情停 900ms 再返回，speed-profile 编译后采集）：
    完整飞行轨迹 19 帧可见（f75@3085ms 起飞 → f94@3251ms 落位），逐帧下边沿
    711→890→983→1066→1138→1198→1249→1291→1326→1355→1381→1401→1419→1433→1445→1454→1462→1468→1473，
    峰值速度在前 1/3、末段 6px/帧——016 的减速落位在新档位下保持；封面与页面
    交叉淡出在同一窗口完成，无"封面先落、页面后缩"。
  - **快速往返**（120ms 后立即返回，普通/speed 两轮）：转场压缩到 2–4 帧内完成，
    逐帧无任何"僵在半路"的冻结帧；此前版本在中断场景下 `begin()` 会被挂起的
    `animateTo` 挡住导致封面冻在半空，接力语义后此现象不再出现（对应 UI 状态机：
    飞行状态随新导航立即清空重起）。
  - 录屏设备侧丢帧严重（有效帧率约 4.5–9fps），逐帧测速仅用于定性；240ms 数值
    以 JVM 钉死 + 模拟器 `mainClock` 测试为准。

## 不做

- 不把路由 280/240 改值（ADR-0009 冻结项）。
- 不做手势进度耦合（navigation-compose 2.9.6 无 seek API，预测式返回继续不做）。
