# 动效地基：自建缩放 + 四层时长表 + ADR-0009

**Blocked by**: 无（与 001 并行，但正式验收排在 001 之后——首帧底噪没清之前，缩放的观感测不准）

## 目标

让"动效时长"这件事从此只有一个来源，并且**第一次**让用户的系统动画缩放真正生效。

## 涉及层

- [x] `ui/motion/MotionTier.kt`：四层时长表（micro 100/120、small 150/200、medium 250/300、
  large 350/450）+ 路由转场一档（280/240，保留现值）；`MotionScale.clamp` / `isSnapped`；
  `MotionSpec.durationMs` / `durationMsOf` / `shouldAnimate` / `staggerOffset`。
- [x] `ui/motion/MotionScaleHost.kt`：`LocalMotionScale` + `MotionScaleProvider` +
  `rememberMotionScale()` + `motionDuration()`。
- [x] `MainActivity`：读系统缩放并挂 `MotionScaleProvider`（挂在主题外面，让 `NavHost` 的转场
  lambda 也读得到）。
- [x] `ui/motion/LyraMotion.kt`：既有的 `slideInto` / `slideOutOf` / `expandFromBar` /
  `collapseToBar` **签名与观感数值不变**，只把字面量换成层级表 × 缩放；`scale ≤ 0.1` 时
  整条转场不发（弹簧没有时长可乘，只能二选一）。
- [x] `ui/theme/Theme.kt`：注释说明为什么不换 Shapes / Typography（**不是**改调
  `MaterialTheme(motionScheme = …)`，原因见下）。
- [x] JVM 单测：`MotionScaleTest`（0 / 0.5 / 1 / 1.5 / 2 / 负值 / `NaN`、四层表 × 缩放、
  `staggerOffset` 的步进与上限）。

## 偏差记录（与计划原文不同，按实测修正）

1. **`MotionScheme.Expressive` 挂不上**：本版锁的 material3 1.4.0 里 `MotionScheme` 接口、
   `MaterialTheme(motionScheme = …)` 重载、`MaterialExpressiveTheme` 都是 Kotlin `internal`
   （`javap` 实测；字节码上显 public 只是 `internal` 的编译方式）。弹簧常量改为从
   `ExpressiveMotionTokens` 抄进 `LyraMotion`，注释标明工具链升级后是唯一替换点。
2. **平台自己已经乘过一次缩放——这条已从"风险"变成"结论"，并修掉了**。
   animation-core 的 `SuspendAnimationKt.doAnimationFrameWithScale` 按
   `coroutineContext[MotionDurationScale].scaleFactor` 缩放所有 spec 动画（**tween 与 spring 都走**
   这条帧循环），而 ui 的 `WindowRecomposer_androidKt.getAnimationScaleFlowFor` 在 recomposer
   创建时读 `Settings.Global.animator_duration_scale` 并注册 `ContentObserver` 喂进去。

   实测（模拟器上的真应用窗口，同一动作"切页后持续渲染时长"，各 3 次）：
   `animator` 1.0 → 980 / 963 / 928ms，2.0 → 1787 / 1751 / 1738ms。
   `clamp` 在 2.0 时必然输出 1.0，所以那 ~1.85 倍只能来自平台。

   **改法**：`LocalMotionScale` 的语义从"想要的倍率"改成"该写进 spec 的乘数"
   （`MotionScale.specMultiplier` = `clamp(animator, transition) / animator`），
   除掉再让平台乘回来。弹簧用等价的刚度换算 `× 1/scale²`（周期 ∝ `1/√stiffness`），
   所以初稿"弹簧没有时长可乘，只能整条播或不播"这句话也不再成立——
   现在只有 `scale ≤ 0.1` 那一档仍然是"整条不播"。

   **默认档零改动**：`animator = 1.0` 时乘数 = 1.0、刚度倍率 = 1。

   **已知残余**：`Modifier.animateItem()` 的两条 spring 由 foundation 内部构造，
   改不到刚度，所以它在 `animator > 1` 时仍会被平台放大；`lyraAnimatedItem` 只保住
   "关掉动画时整条不播"。根治要传显式 spec，本版不做。
3. **仪器测试量不到第 2 条**：模拟器 `animator_duration_scale = 0` 时，一个
   `animateFloatAsState(tween(2000))` 走 200ms 仍只到 ~0.1。测试环境自带 recomposer 与时钟，
   与生产的窗口 recomposer 不是同一条链。**要量就得跑真应用窗口**：改设置 → 冷启动 →
   数帧或看墙钟。已收进
   [`../../../../scripts/measure-transition-duration.ps1`](../../../../scripts/measure-transition-duration.ps1)
   （静止时一帧不画，所以"点一下之后数帧"就是时长的有效代理量）。

## 验收标准

- JVM 单测覆盖：`clamp` 的 0 / 0.5 / 1 / 1.5 / 2 / 负值 / `NaN`；四层时长表 × 缩放的结果；
  `staggerOffset(step = 40, cap = 240)` 的边界。
- 模拟器：把系统动画时长改成 0 后进详情页，页面**当帧**到位（不是"很快地滑一下"）。
- **三档复核**：0 / 0.5 / 2.0 各量一次。**数值部分已过**——在真应用窗口上按
  "音乐库 → 我喜欢"这一条只有路由转场的隔离场景数帧：
  `1.0` → 42/43/44/43 帧，`2.0` → 44/40/43/44（与 1.0 一样，证明"不放大"真的生效了），
  `0.5` → 25/22/24/25（半速）。原始对照表在 CHANGELOG 的"决策 1"。
  **剩下的只有观感**：PLK110 上目视按压与转场的手感对不对。**未跑**（设备掉出 adb）。
- 路由转场数值与 `BlurBackdrop` 的 450ms / radius 不动：改动前后同场景 `gfxinfo` 对照。
