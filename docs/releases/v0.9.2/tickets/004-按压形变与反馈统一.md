# 按压形变与反馈统一

**Blocked by**: 002

## 目标

"点了没反应"在本项目里从来不是缺涟漪——`LocalIndication` 一直在给 ripple。缺的是**属于被点
物体自己的形变**：ripple 抹平了"这是可点的"，按压形变才回答"我点到的就是这一行 / 这一张卡"。

## 涉及层

- [x] `ui/common/LyraPressable.kt`：`Modifier.lyraPressable(onClick, …)`（行 / 卡片）与
  带 `onLongClick` 的重载（`TrackRow` 走这条）；`Modifier.lyraPressScale(interactionSource)`
  只挂形变、不接管点击。
- [x] 落点：`TrackRow`、`PlaylistCard`、`LibraryScreen` 的入口卡、`SourcesScreen` 的音源卡、
  `LyraApp` 的 `MiniPlayerBar`、`SavedPlaylistsScreen` 的行。
- [x] 参数：起 1.00，按下 0.98（行 / 卡）或 0.94（图标 / 点），100ms 无过冲；抬起 120ms 回 1.00；
  ripple 沿用 `LocalIndication`，不重复实现。

## 为什么卡片要拆成两个挂点

自带底色或容器的卡片（音乐库入口、音源卡）里，"形变"与"点击"必须挂在链上的两个不同位置：

- 形变挂在外层，否则只有内容在缩、卡片底色不动；
- 点击留在底色**里面**，否则涟漪被画在底色下面，等于没有。

两个位置隔着 `clip` / `background`，靠传同一个 `interactionSource` 对齐。

音源卡是另一种情况：整张卡本来就没有点击（点卡片什么也不做），所以它把卡片上那两个控件
（开关、删除）的按压状态接过来——按哪个都是"我在按这一张卡"。

## 验收标准

- 模拟器截图 + 真机目视：按下时形变看得见，抬起后回到 1.00，没有"整行在跳"的感觉
  （行只缩 2%，再多就会在列表里看出来）。
- `MotionScaleProvider(0f)` 下点击照样生效，只是不缩（见 002 的 ui-test）。
- 长按 `TrackRow` 仍走"更多操作"，行为不变。
