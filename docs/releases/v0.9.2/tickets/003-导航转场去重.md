# 导航转场去重：lyraDetailRoute + RouteKind

**Blocked by**: 002（要用 `MotionSpec` 的换算）

## 目标

`LyraApp.kt` 里那四个转场参数此前一字不差地抄了 **13 遍**（进 / 出 / pop 进 / pop 出 +
四个 lambda 里的判断）。抄错一条的表现是"某一页底下的 Tab 页跟着一起滑"——两个界面同时在动，
而那正是三轮真机验收反复修掉的东西。收成一处之后，转场只有一个改动点。

## 涉及层

- [x] `ui/nav/LyraRoutes.kt`：路由常量、`RouteKind`（TAB / DETAIL / PLAYER / UNKNOWN）、
  `DETAILS` 表（13 条，含参数名与类型）、`kindOf` / `isDetail`、路径构造函数。
  **纯 Kotlin，不碰 Compose**，所以分类这件事可以写成 JVM 单测。
- [x] `LyraApp.kt`：抽 `private fun NavGraphBuilder.lyraDetailRoute(route, motionScale,
  innerPadding, arguments, content)`；13 个调用点各一行；`ROUTE_PLAYER` 保留独立注册
  （"从迷你播放条长出来"是另一套观感）。Tab 那一档的 `exitTransition` / `popEnterTransition`
  改问 `LyraRoutes.isDetail(...)`。
- [x] JVM 单测 `LyraRoutesTest`：14 条路由全覆盖、player 独立、UNKNOWN 归详情策略；
  再加两条**源码扫描守卫**（对 `LyraApp.kt` 与 `LyraRoutes.kt` 本文做断言），防止有人再把
  转场参数抄回调用点。

## 行为不变的部分（刻意）

Tab 的进出位移、详情页的进入方向、播放页的 280 / 240、`BlurBackdrop` 的 450ms 与"radius 不动"
（ADR-0005）全部照旧。本片只改**取值方式**，不改观感。

## 验收标准

- JVM 单测：13 条详情路由 + 3 个 Tab + player 的分类全部命中，且 player 不在详情表里。
- 模拟器：逐页走一遍（音源 / 设置 / 缓存 / 我喜欢 / 我的歌单 / 收藏的歌单 / 本地音乐 /
  歌单广场 / 榜广场 / 专辑 / 歌单 / 榜详情 / 自建歌单 + 三个 Tab + 播放页），
  每一页底下的 Tab 都不跟着滑。
- `gfxinfo`：转场首帧与 001 的口径一致，不因去重变差。
