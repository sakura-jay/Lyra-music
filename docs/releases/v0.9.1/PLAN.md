# Lyra v0.9.1 计划（M8 补丁）

> 本版不是里程碑，是 `v0.9.0` 双轴代码审查的收口批次。审查结论与逐条现状在

## 1. 范围从哪来

`v0.9.0` 发布后按标准轴（仓库规范 + 异味）与规格轴（PLAN 的 A/B/C/D 用户故事）各审一遍，
产出三档待办：P0（不依赖需求就该修）、P1（改行为，与规格轴同根）、P2（结构性异味）。
本版把这三档加规格轴里能靠代码补的全部做完，**没有新增任何用户可见功能**。

## 3. "完成长什么样"

- `:app:compileDebugKotlin` + `:app:compileDebugAndroidTestKotlin` + JVM 单测绿。
- 模拟器（Pixel_8 / Android 17）全量 instrumented：**129 条 0 失败 0 错误**，允许既有网络探针跳过。
- `:app:lintDebug` 0 error。
- 观感项在模拟器上逐屏截图走过（首页两排、榜单广场、榜单详情含失败态与重试、音乐库四卡片、
  我喜欢页整链路）；见 `REVIEW.md` 第 6 节。
- **发布前还差**：`app-release.apk`（R8）在真机 PLK110 冒烟一遍——音源取址、播放、歌词背景、
  榜卡片封面、备份导入导出。历史上 R8 真出过问题，这一条不能省。
  注意 release 与 debug 签名不同，覆盖装会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，
  需先卸载；**JSON 导出不含音源**，事先备好音源文件。
- 真机冒烟通过后再打 tag `v0.9.1`。

## 4. 明确不做（留给 M9）

- **共享翻页件**：`LeaderboardDetailViewModel` 与 `PlaylistSquareViewModel` 那份分页状态机仍是两份。
  P1 只改了榜单侧的语义（`total` 可空、失败不等于到底、`failed` 与空榜分开），两边现在不同构，
  此时抽取是设计不是清理。M9 先对齐语义再抽，`LeaderboardDetailPagingTest` 七条是回归线。
- **图片库**：位图缓存抬到 48 张只是让 D1 的兑现范围盖住广场 36 张；再往上就该换库而不是改常量。
- 榜单开音源通道、QQ 音乐 / 咪咕来源、我喜欢排序筛选批量编辑、"不缓存 / 无上限"档——
  仍沿用 `v0.9.0` PLAN §6 的"明确不做"。
