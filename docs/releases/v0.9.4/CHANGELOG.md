# v0.9.4 变更记录（观感与性能收口）

两片，都是从 v0.9.3 的「未完成 / 用户反馈」里长出来的补丁：
[PLAN.md](PLAN.md) 定计划，[tickets/](tickets/) 逐片取证，
[PROMPTS.md](PROMPTS.md) 给英文实现提示词。

- **015 `BlurBackdrop` 降采样**：播放页那层全屏模糊在 1/4 尺寸的图层上做、
  再放大画回全屏。忙帧 GPU p50 **7.82 → 4.03ms（降 48%）**；
  120Hz 预算（8.33ms）超限的忙帧 **62.0% → 2.8%**。
  同曲同图截图的干净背景带逐像素平均差 < 1、边缘梯度比 1.000——观感无变化。
  顺带把交叉淡出那条裸 `tween(450)` 接上 `LocalMotionScale`（基准 450 不变）。
- **016 共享元素回程缓动**：回程从加速曲线（`FastOutLinearIn`）换成减速落位
  （`FastOutSlowIn`）。真机逐帧量到：峰值速度的位置从 **93% 挪到 33%**，
  末 10% 时间的位移占比 **12.6% → 5%**——"越走越快、撞进终点"收掉了。
  去程保持原曲线不动（对照组量过）。

## 摘要（面向用户）

- 从播放页返回时，封面飞回来路那张卡片的速度曲线修好了：现在中段最快、
  越接近卡片越慢、轻轻落位；不再"慢慢起、越走越快、一脚刹车没有"。
- 播放页背景模糊便宜了一半（GPU 侧），观感没有任何变化。
- 系统动画缩放关掉时，背景换封面的交叉淡出也跟着关（之前是一处漏网）。

## 决策 1：015 缩放挂父层、模糊留子层

高斯模糊与缩放近似可交换，所以"先在 1/4 尺寸模糊、再放大 4 倍"观感等价、
像素量降到 1/16。**顺序不能反**：先放大再模糊，`RenderEffect` 作用在已放大的内容上，
半径与像素量都回到原点，等于没改。

源位图进来前已被 `ArtworkLoader` 降到 ~256px，全屏那层一直都在被放大——
再乘 4 的双线性插值比 26dp 模糊细一个数量级，这就是观感 A/B 像素级相同的原因。

### 平台 `Janky frames` 那栏为什么不动

A 5.48% → B 5.67%，几乎没变。**这条不要当证据用**：它的分母是整个场景
712/706 帧（包含静止段），而改动只影响忙帧。两份的平台数字只说明
"场景里多数帧本来就不忙"。本片的判据是忙帧口径（`analyze-framestats.ps1`，
与 v0.9.3 决策 9 同一套）。

### 一张作废的截图

`b2-NEON.png` 的背景均值是中性灰（245/247/245）——封面图没加载出来，
那张不能当 B 的证据。有效的是 `b3-NEON.png`（背景均值 175.5/157.6/152.7，
与 A 的 175.1/157.5/152.7 同曲同图）。第一版比较用了 `b2`，结论作废重比。

## 决策 2：016 为什么"出场加速"在这里是错的

Material 的"入场减速、出场加速"约定，前提是**出场的东西会消失**——
加速离开屏幕没问题，没人看它落在哪儿。

共享元素的回程不消失：它要精确落回一张就在用户眼前的卡片。
最后那一段正是眼睛盯着的那一段，加速曲线 = **以最高速撞进终点**。

`FastOutSlowInEasing` 是无过冲的 cubic-bezier（ADR-0009 护栏一：全屏位移不许过冲），
起步有一小段加速所以不像被拽走，中段最快，尾段减速落位。

### "匀速"这个用户描述其实低估了问题

逐帧量出来不是匀速，是**加速**：改前回程峰值速度出现在 **93%** 处，
末 10% 时间走掉 **12.6%** 的位移。匀速的对应值是 10%——
所以真实观感比"匀速"更差，用户的感觉是对的，措辞偏保守了。

## 订正：v0.9.3 的 247ms 是量法错误，不是应用快了

011 工单记过「`dy=188→…→0` 跨 247ms，与规格 350ms 差约 100ms，未解释」。
本版重量后发现那个 247ms 本身是错的：

1. 起止帧是**肉眼挑**的，不是差分定义的"第一/最后一帧有变化"；
2. 模板匹配跨了**三段不连续的录像片段**（两处 1.9s / 1.2s 的时间戳空隙），
   空隙没剔除，直接当连续动画量了时长。

正确方法（差分定起止、跳变剔除、`pts_time` 算间隔）重测同一份录像：
**去程实际 274–299ms**，与规格一致。不是应用快了 100ms，是原来的量法错了。
[011 工单](../v0.9.3/tickets/011-歌单与榜单卡片与详情页头封面共享.md)已订正。

这是本项目第九次抓到同一类循环论证（"先挑一段看着像在动的帧区间、再把区间跨度当时长"）。
判据已固定：**起止帧由逐帧差分定义、时间用 `pts_time`、跳变帧剔除**。

## 已知边界

- **Jank 门槛没有动**：硬门槛仍只考核"列表/广场滚动 + 转场首帧"两个场景。
  播放页忙帧 GPU 那组数（62% → 2.8%）只是 015 的验收证据，不是新门槛。
  要把 120Hz 忙帧预算收进正式门槛，需单独拍板，不许顺手发生。
- 010（迷你条 ↔ 播放页）的回程没有单独录；两条路由共用同一处 `coverFlightEasing(enter = false)`，
  代码层同一改动，010 的逐帧复测留给下一轮走查。
- 016 尾段每帧只剩 4–6px 位移，与模板匹配精度（±2px）同量级——
  "撞进终点消失"这个定性结论可靠，5% 里的逐帧精确值这个工具给不了。
- Perfetto 仍欠（v0.9.2 起挂账）：`framestats` 的 GPU 段能定位成本量级，
  但"GPU 段里到底是谁"要 trace 才能拆。
- 手机 `svc power stayon true` 在测试期间保持开启，**收尾时已恢复为 `false`**。
