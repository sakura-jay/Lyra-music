# 015 `BlurBackdrop` 降采样

**主交互**：无匹配模式（普通实现）

## 目标

播放页那层全屏 `RenderEffect` 模糊背景是忙帧 GPU 的主要成本（v0.9.3 决策 9 已归因）。
本片把它换到 1/4 边长的图层上做、再整体放大回全屏，被处理的像素降到约 1/16；
同时把交叉淡出那条裸 `tween(450)` 接上 `LocalMotionScale`（ADR-0009 的缩放契约）。

观感约束一条不动：**450ms 交叉、radius 不动、两层交叉淡出**（ADR-0005）。

## 涉及层

- [x] `ui/player/BlurBackdrop.kt`：新增 `BACKDROP_SCALE = 0.25f`；两层 `BlurLayer`
  改成 `fillMaxSize(0.25)` + `blur(radius × 0.25)`；外面套一层 `graphicsLayer`
  以 `TransformOrigin(0, 0)` 放大 4 倍画回全屏。
- [x] 交叉淡出接 `MotionSpec.durationMs(MotionTier.LARGE, scale, enter = false)`；
  `!shouldAnimate` 时直接 `snapTo(1f)`，整条交叉不播。
- [x] 不改任何布局尺寸、不改 radius、不改两层交叉的结构。
- [x] 不加任何依赖。

## 为什么缩放必须挂在父层、模糊留在子层

高斯模糊与缩放近似可交换：`blur(r)` 后放大 s 倍 ≈ 放大 s 倍后 `blur(r·s)`。
所以**先在 1/4 尺寸上模糊、再把图层放大 4 倍**，观感等价、像素量降到 1/16。

反过来写（先放大再模糊）会让 `RenderEffect` 作用在已经放大过的内容上，
半径与像素量都回到原点，等于没改。

PLK110 上：1272×2772 → 318×693。源位图进来前本来就已被 `ArtworkLoader` 降到 ~256px，
全屏那层一直都在被放大——放大带来的双线性插值比 26dp 的模糊细一个数量级，
所以这层再加 4 倍放大不会引入可见的模糊度变化。

## GPU A/B（PLK110 release 包，`scripts/measure-motion.ps1 -Mode Player`）

三份采集都是同一协议（迷你条 ↔ 播放页 6 次往返、同曲 NEON、`framestats` 只看最后 120 帧）。
分析工具 `scripts/analyze-framestats.ps1 -BudgetMs 8.3333`（120Hz 一档），忙帧口径同决策 9：

| 采集 | 忙帧 | 忙帧成本 p50 | 超 8.33ms | 忙帧 GPU p50 |
| --- | --- | --- | --- | --- |
| v0.9.3 线（`build/phone-player`） | 109 | 8.17ms | 50（45.9%） | 6.99ms |
| 本轮 A（旧实现再采一份，`build/blur-A`） | 108 | 9.40ms | 67（62.0%） | 7.82ms |
| 本轮 B（降采样后，`build/blur-after`） | 107 | **5.29ms** | **3（2.8%）** | **4.03ms** |

- **忙帧 GPU p50：7.82 → 4.03ms，降 48%。**
- **120Hz 预算超限：62.0% → 2.8%。**
- 平台口径 `Janky frames` 几乎不动（5.48% A → 5.67% B）——**这条不要当证据用**。
  它的分母是整个场景 712/706 帧（包含静止段），而改动影响的是忙帧。
  两份采集的平台数字只说明"整个场景的多数帧本来就不忙"，不说明改动无效。
- `build/phone-player` 那份是 v0.9.3 线的历史采集，与本轮 A 的差（6.99 vs 7.82）就是
  同一实现两次采集的离散度——所以 A/B 结论用的是**同轮采集的两份**，历史那份只做量级对照。

## 观感 A/B（同曲 NEON，像素差分）

截图 `build/blurab/a2-NEON.png`（旧）vs `b3-NEON.png`（新），背景纯模糊带三块：

| 区域 | meanAbsDiff | maxDiff | 梯度比 A→B |
| --- | --- | --- | --- |
| 左上背景带 | 0.76 | 4 | **1.000** |
| 右上背景带 | 0.68 | 3 | **1.000** |
| 左中背景带 | 3.91 | 464 | 0.818 |

前两带是干净的背景区：逐像素平均差 < 1（8bit 量化的噪声级），
边缘梯度比精确到三位小数 = 1.000，**模糊度没有变化**。

第三带的差是**混淆变量**，不是 blur 的差：那块区域包含进度条与时间文字，
A 截在 0:48、B 截在 3:41（播放位置不同），maxDiff 464 就是文字与进度条自己。
判定方法：先看背景均值（A `175.1/157.5/152.7` vs B `175.5/157.6/152.7`）与封面均值
（两份 `167.9/148.0/138.8`，完全相同）——同曲、同图、同背景，可以比。

**作废一张截图**：`b2-NEON.png` 的背景均值是 `245/247/245`（中性灰），
封面图根本没加载出来，那张不能当 B 的证据。有效的是 `b3-NEON.png`。

## 缩放契约

裸 `tween(450)` 是 v0.9.2"让系统动画缩放真正生效"那条的漏网——
当时 ADR-0005 把"450ms 交叉"列为保持项，这一条因此被跳过了。

本版把它接上但不改基准：`MotionSpec.durationMs(LARGE, scale, enter = false)` 的基准
就是 450ms（`MotionTier.LARGE` 的退出档），所以 scale=1 时行为不变；
scale=0 时整条交叉不播、直接 `snapTo(1f)`（判据同 ♥ 与页码：不动画就不读动画值）。

## 验收标准

- 忙帧 GPU p50 显著下降（量到：7.82 → 4.03ms）。**量过。**
- 同曲同图下背景区像素差在量化噪声内（量到：meanAbsDiff < 1、梯度比 1.000）。**量过。**
- 450ms 交叉与 radius 不动（代码可证：`radius × BACKDROP_SCALE` 与父层 4 倍放大抵消，
  交叉时长基准仍是 LARGE 退出档 450ms）。**读过代码。**
- 缩放契约接上（`LocalMotionScale` + `shouldAnimate` 早退）。**读过代码；未单独像素测
  "scale=0 时第一帧"——它是 `Animatable.animateTo`，不是 `animate*AsState`，
  两张位图与 alpha 在同一个 `LaunchedEffect` 里一次落，不属于"晚一帧"那一族（同 v0.9.3
  决策 8 表里那行的结论）。**
- JVM 140 条全绿（`--rerun-tasks`，2026-10-21 16:18）。**量过。**
- instrumented 172 条全绿（emulator-5554，2026-10-21 16:44，`Time: 189.968`）。**量过。**
- `:app:lintDebug --rerun-tasks` 0 error / 5 warning（2026-10-21 16:45）。**量过。**

## 未做 / 边界

- **Jank 门槛没有动**：硬门槛仍只考核"列表/广场滚动 + 转场首帧"两个场景。
  播放页忙帧 GPU 那组数（62% → 2.8%）只是本片的验收证据，**不是新门槛**。
  要把 120Hz 忙帧预算收进正式门槛，得单独拍板并写进 CHANGELOG，不许顺手发生。
- **Perfetto 仍欠**（v0.9.2 起挂账）：`framestats` 的 GPU 段已经能给出结论，
  但"GPU 段里到底是谁"要 trace 才能拆。
- 降采样倍率 0.25 没扫过别的档（0.5 / 0.125）：0.25 已经把超预算压到 2.8%，
  再降一档对观感的风险大于收益。
